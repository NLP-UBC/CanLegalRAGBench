# Generation Evaluation

Evaluates end-to-end RAG answer quality: answers are generated from a retrieval run's
results, then judged against the human-written reference answers with Ragas.

## Pipeline

```
../evaluate_retrieval/runs/<experiment>/results/query_results.jsonl
        │
        ▼
generate_answers.py     build context from the retrieved chunks (full documents
        │                 when they fit a 115k-token budget, otherwise chunks +
        │                 truncated documents) and generate an answer per query
        │                 with Gemini; answers are written back into query_results.jsonl
        ▼
prepare_eval_input.py   join generated answers with the benchmark's reference
        │                 answers → outputs/answers.jsonl
        ▼
ragas_answer_eval.py    Ragas judge: groundedness of the generated answer in the
                          reference answer (dual-judge, 0-1), optionally factual
                          precision (claim decomposition + per-claim NLI verdicts)
```

## Setup

Install dependencies from the repository root (`pip install -r ../requirements.txt`; the judge
needs `ragas>=0.4`). Set `GOOGLE_API_KEY` (or `GEMINI_API_KEY`) in a `.env` file here — used
by both the generator and the judge. `--provider openai` for the judge needs
`OPENAI_API_KEY` instead.

A completed retrieval run in `../evaluate_retrieval` is the starting point (its
`query_results.jsonl` must contain `retrieved_chunk_details`, which `run_benchmark.py`
saves by default).

## Running

```bash
# 1. Generate answers for a retrieval run
python generate_answers.py \
    --config ../evaluate_retrieval/configs/experiments/qwen_recursive_8192.yaml

# 2. Join with the reference answers
python prepare_eval_input.py \
    --results ../evaluate_retrieval/runs/qwen_recursive_8192_1k-docs/results/query_results.jsonl \
    --generator gemini-2.5-flash --retrieval-method qwen_recursive_8192

# 3. Judge with Ragas (gemini-2.5-pro judge by default)
python ragas_answer_eval.py --keep-answers --also-factual-precision
```

Outputs land in `outputs/`: per-row scores (`groundedness_scores.jsonl` / `.csv`) and an
aggregate `groundedness_summary.json`.

Answers generated by other means can also be judged directly — step 3 only needs a
json-lines file with `query_text`, `generated_answer`, and `ground_truth_answer` fields
(field names configurable via `--query-field` / `--response-field` / `--gold-field`).

## Auditing the judge

- `--manual-eval` runs the judge on a single row and dumps the decomposed claims,
  per-claim verdicts with reasons, and the exact prompts sent to the judge
  (`outputs/manual_eval/`, JSON + Markdown).
- `--llm-log-jsonl outputs/judge_trace.jsonl` records every judge call (prompt, output,
  and row context) for post-hoc inspection.

## Notes

- The answer prompt (`benchmark_rag/prompts/answer_generator.py` in
  `../evaluate_retrieval`) instructs the generator to produce the same three-section
  structure the human annotators used for reference answers, so generated and reference
  answers are directly comparable.
